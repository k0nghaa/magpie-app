# M2.5 iOS AlarmKit 스파이크 — 빌드 & 실기기 테스트

> 목적: iPhone(iOS 26.6.1)에서 **(1) 알람이 무음/잠금/DND를 뚫고 실제로 울리는지**,
> **(2) 알람의 [대화 시작] 버튼으로 앱이 실행되며 대화 세션이 시작되는지**,
> **(3) 완전 종료 상태에서도 되는지**를 실증한다. 여기서 치명적 문제가 나오면 방향을 재검토한다.

## 0. 왜 재빌드가 필요한가 (Expo Go 불가)
이번 변경은 **네이티브**다 — 커스텀 Swift 모듈(`modules/expo-real-alarm`), Info.plist(`NSAlarmKitUsageDescription`),
App Group 엔타이틀먼트(`group.com.k0nghaa.magpie`). JS OTA로는 반영 불가. **EAS development 빌드를 1회 재생성**해야 한다.

## 1. EAS dev build 재생성 (Windows)
이 프로젝트는 managed/CNG(로컬 `ios/` 폴더 없음, `.gitignore`에 `/ios`)라 **로컬 prebuild는 불필요·불가**하다.
Windows에서 `npx expo prebuild -p ios`는 "Skipping generating the iOS native project files"로 건너뛰고
"At least one platform must be enabled"만 뜬다 — 정상. prebuild는 **EAS가 클라우드(macOS)에서 자동 실행**한다.

```bash
# EAS 클라우드 빌드 (macOS Xcode 26.6 러너) → internal distribution 링크로 아이폰 무선 설치.
# 여기서 클라우드가 prebuild + CocoaPods + Swift 컴파일을 한다(= Swift 컴파일 리스크가 드러나는 지점).
eas build --profile development --platform ios
```
- **App Group capability**: EAS 관리형 크리덴셜이 `ios.entitlements`의 App Group을 Apple Developer 포털에 동기화한다.
  빌드 로그에서 "App Groups" capability가 앱 ID에 추가/동기화되는지 확인. (동기화 실패 시 포털에서 `group.com.k0nghaa.magpie` 생성 후 재빌드)
- 설치 후 Metro: `npx expo start --dev-client` (JS는 로컬 Metro가 번들 — `.env`의 EXPO_PUBLIC_* 키가 인라인됨)

## 2. ⚠️ Swift 컴파일 리스크 지점 (첫 빌드에서 실패하면 여기부터)
AlarmKit은 iOS 26.x에서 시그니처 드리프트가 보고됐다. 컴파일 에러가 나면 `modules/expo-real-alarm/ios/RealAlarmModule.swift`에서:
1. **`secondaryButtonBehavior: .custom`** — SDK에 `.custom` 케이스가 없으면 에러. Xcode Quick Help로 `AlarmPresentation.Alert`의 `secondaryButtonBehavior` 실제 케이스 확인(대안: `.countdown`).
2. **`countdownDuration: nil`** — 이 파라미터가 옵셔널이 아니면 nil 거부 → `Alarm.CountdownDuration(preAlert: nil, postAlert: nil)`로 교체.
3. `sound: .default`(`AlertConfiguration.AlertSound`) 타입 모호 시 `ActivityKit.AlertConfiguration.AlertSound.default`로 한정.

에러 메시지를 그대로 보내주면 정확히 짚어 고친다.

## 3. 실기기 테스트 체크리스트
> 스파이크 패널은 본구현에서 제거됨. **설정 화면의 실제 흐름**으로 검증한다:
> 설정 → 시간을 **지금+1~2분**으로 맞추고 [이 시간으로 알림 켜기] → 저장 시 AlarmKit 권한 팝업 허용 →
> 화면 끄고(무음 ON) 대기. (매일 반복이므로 한 번 맞춰두면 이후 매일 같은 시각에 울림)

- [ ] **권한**: 저장 시 알람 권한 팝업 → 허용 → "현재 예약: 매일 HH:MM" 표시
- [ ] **핵심(무음+잠금)**: 시간을 지금+1~2분으로 저장 → **무음 스위치 ON + 화면 잠금** 후 대기 → **알람이 소리내며 울리는가**
- [ ] **집중/DND**: 집중(Focus)/방해금지 모드 켠 상태에서도 울리는가
- [ ] **버튼→앱→대화**: 알람에서 **[대화 시작]** 탭 → 앱이 열리고 → 대화 화면으로 전환되며 → "연결 중…"→대화 시작되는가
- [ ] **밀어서 끄기→앱→대화**: 정지 컨트롤을 밀어도 앱이 열리고 대화가 시작되는가 (2026-09-08 변경: 밀어서 끄기도 앱 실행+대화 시작). 스와이프 해제 시 stopIntent 미발화 버그가 있으면 여기서 앱이 안 열릴 수 있음 → 버튼 경로와 비교
- [ ] **완전 종료(cold start)**: 예약 직후 앱을 **스와이프로 완전 종료** → 알람 대기 → [대화 시작] → 앱이 새로 실행되며 대화 시작되는가 (브릿지 핵심 검증)
- [ ] **재부팅 지속성**: 예약 후 기기 재부팅 → 남은 시간에 알람이 울리는가 (문서상 미보장 항목 — 실측)
- [ ] **스와이프 해제 회귀**: 알람을 버튼 대신 스와이프로 해제 → 이후 상태 이상 없는가 (stopIntent 미발화 버그 보고 있음)
- [ ] **26.2류 무음 회귀**: 알람이 아예 안 울리는 경우 없는가 (26.1→26.2 회귀 보고 있음 — 26.6.1에서 확인)
- [ ] **알람음 반복/지속**: `.default` 알람음이 끊기지 않고 지속 울리는가
- [ ] **오디오 세션**: [대화 시작]으로 진입한 대화에서 스피커 볼륨·반이중(에코 없음)이 정상인가 (알람음→playAndRecord 전환 부작용 확인)

- [ ] **매일 반복(핵심 게이트)**: 발화 → **[대화 시작] 또는 밀어서 끄기로 해제** → **다음 날 같은 시각에 다시 울리는가**. 여기서 안 울리면 stop이 반복 스케줄까지 지운 것 → 보고(인텐트의 stop 호출 제거로 대응). Settings에도 시각이 유지되는지 함께 확인.
- [ ] **끄기/재예약**: [알림 끄기] 후 예약 해제, 다른 시각으로 다시 저장 시 중복 없이 새 시각만 울리는가
- [ ] **fallback(선택)**: iOS<26 기기가 있으면 M2 일반 알림으로 예약되고 탭→대화 시작되는가
